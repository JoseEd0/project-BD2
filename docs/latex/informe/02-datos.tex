\section{Dominio de datos}

Se usan dos conjuntos de datos.

\paragraph{Dataset de comercio electrónico (generado).} Modela clientes, pedidos, productos
y categorías, además de tiendas con ubicación en Lima. Son seis tablas y cerca de
30\,000 filas (tabla~\ref{tab:dataset}). Las tablas usan distintas organizaciones e
índices, para poder mostrar todas las estructuras con los mismos datos.

Los datos se generan con \texttt{demos/poblar\_ecommerce.py} a partir de una semilla fija,
por lo que siempre salen iguales; el tamaño se cambia con la opción \texttt{-{}-escala}.
Los seis CSV están en el repositorio y se pueden cargar desde la interfaz. Las tiendas se
ubican dentro de doce distritos de Lima, lo que permite verificar consultas como
\guillemotleft{}tiendas dentro de Miraflores\guillemotright{}.

\paragraph{Lugares de OpenStreetMap (reales).} Para la parte espacial se necesitaban puntos
con una distribución real y no uniforme. El script \texttt{demos/descargar\_lugares.py}
descarga de Geofabrik los puntos de interés del Perú (colegios, restaurantes, farmacias,
bancos, gasolineras, etc.) y genera un CSV con las columnas \texttt{id}, \texttt{nombre},
\texttt{rubro} y \texttt{ubicacion}, donde la ubicación tiene el formato
\texttt{POINT(latitud, longitud)}. En total son 128\,011 lugares con nombre, de los cuales
26\,606 están en Lima y Callao. Este dataset se usa en el experimento espacial y en la
demostración del mapa.

\paragraph{Tipos de datos.} El gestor soporta enteros, reales, booleanos, fechas, texto de
longitud fija, bytes y puntos. Al cargar un CSV, el tipo de cada columna se infiere de sus
valores. Las comparaciones solo se permiten entre tipos compatibles: por ejemplo,
\texttt{WHERE id = 'abc'} da un error que indica la columna, en lugar de devolver cero
filas.
